# Writing guide

The framework deliberately narrows the writing surface: one markdown file plus at most six frontmatter keys, everything else derived from the directory structure at build time. This page is the daily-writing cheat sheet; syntax details live in [Markdown extensions](./markdown.md).

## A file is a page

Every `**/*.md` under `contentDir` is a page, routed as `<relative path>.html`; `index.md` is the index page of its directory:

```text
content/
├── index.md              # home page /index.html
├── notes/foo.md          # /notes/foo.html
└── notes/index.md        # /notes/index.html; the directory row links here
```

Directories are categories: the sidebar is generated from directories, a folder row links directly to that directory's `index.md`, and the row label takes the first h1 of `index.md` (falling back to the directory name when no index page exists); the index page does not repeat among its own children. So "moving a file" is "moving a page" — navigation, archives, and the related graph all follow automatically. The generated order is alphabetical; adjust it with `sidebar.order` / `sidebar.tweaks` (see the [configuration reference](./configuration.md#sidebar)).

## Titles and page names

The page title is the **first h1** in the content; sidebar, TOC, archives, the home article feed, and RSS all consume it. A page without an h1 has an empty title and falls back to its file path in navigation. Heading anchors are generated by the same slugify as VuePress 2 (ported from @mdit-vue/shared), character-for-character identical to VuePress (non-ASCII kept as-is, English lowercased, spaces become hyphens). Internal references look like `[Configuration reference](./configuration.md#basic-fields)`.

## The six frontmatter keys

Only `date` / `category` / `tag` / `icon` / `feed` / `overview` are recognized; other keys are ignored:

```md
---
date: 2026-10-03 # ISO string or yyyy-MM-dd; article feed ordering and RSS pubDate
category:
  - guide # category archive pages (multi-value)
tag:
  - writing
  - markdown # tag archive pages (multi-value)
icon: rocket # must be a key registered in the site config icons map
feed: true # default true; false opts out of RSS (the article feed still includes it)
overview: true # default true; only meaningful on a directory's index.md
---
```

- `date` decides the reverse-chronological position in the home article feed and archives; when omitted, the page sorts before undated articles by route name as a fallback
- `icon` is validated at build time: an unregistered key is a build error. Icon values are full `<svg>` strings or bare SVG inner markup, registered once in the site config; frontmatter only references the key
- `overview` only matters on a directory's `index.md`: set to `false`, the navbar panel no longer shows an overview row for that directory (neither in top-level panels nor in synthesized second-level folder panels); the folder row still links to it, and the sidebar and mobile drawer are unaffected
- Password-protected pages should set `feed: false` so titles and links do not leak into the feed — see [Encryption](./encrypt.md)

## Dates: write one by hand, git handles the rest

- `createdAt` comes from frontmatter `date` and drives article feed ordering
- `updatedAt` is the file's **last git commit time** (queried in batch at build time); outside a git repository (or for untracked files) it is `null`, and the page shows no update time

So daily writing only needs one `date` written at creation; "last edited" is maintained by git with no manual syncing.

## Internal links and dead link checking

Relative links starting with `./` `../` are resolved at build time; a failure is a build error, so broken links cannot be published. Always cross-link articles with relative paths carrying the `.md` suffix (`./related.md`, cross-page anchors like `./related.md#section`): they are protected by dead link checking and friendly to editors when files move. Resolve order, asset passthrough, and bare-link policy are covered in [Markdown extensions](./markdown.md#site-links-and-dead-link-checking).

## Images

Relative-path images are copied at build time under content-hash names, with `src` rewritten per page depth, so deploying under any sub-path keeps them working. An image alone in a paragraph is upgraded to `<figure>` (alt becomes figcaption), and the `![alt](src =WxH)` size syntax is supported; all forms and rules are in [Markdown extensions](./markdown.md#images). For screenshots that need click-to-zoom, use the ZoomedImg island — see [Islands](./islands.md#zoomedimg).

## Recommended writing flow

1. Create `xxx.md` in the right directory, write the h1 and frontmatter (at least `date`)
2. Organize content with the syntax from [Markdown extensions](./markdown.md); code blocks have line numbers by default and auto-collapse past 15 lines, no need for screenshot-as-code
3. Cross-link related articles — the build aggregates mutual references into the [related-article graph](./configuration.md#related)
4. Verify with `pnpm build` or the dev server: dead links and icon errors surface at build time
